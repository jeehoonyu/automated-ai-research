# Benchmark

A small, fully synthesized corpus and a table of cases that each seed one defect — and name the
**specific mechanism** that must catch it.

```bash
python benchmark/build_corpus.py /tmp/corpus     # inspect the documents
pytest tests/benchmark -q                        # run the benchmark
```

## Why the cases name a mechanism

A test asserting only *"publication was blocked"* passes when the **wrong** gate fired, or when
everything failed for an unrelated reason. `benchmark/expected/cases.json` therefore records, per
case, the check that must fire and the status it must report. The harness asserts that exact pair.

This is the same discipline as `docs/lessons-carried-forward.md` §6c — but **it holds for six of the
25 checks, not all of them**, and the sentence here used to claim otherwise ("deleting any single
check must break at least one assertion"). Measured: removing `check_source_hashes`,
`check_visual_certainty`, `check_lifecycle`, `check_independence`, `check_artifacts_conform` or any
of the four review-completeness checks from `CHECKS` leaves this benchmark green. Those gates are
covered by the unit and integration suites instead; the gap is in the *benchmark*, which is the
thing that claims to measure end-to-end coverage.

The six the benchmark does pin are listed in `docs/validation-rules.md`, and
`tests/unit/test_vocabularies.py` fails if that list and `cases.json` disagree — so this paragraph
cannot quietly become true again by wishful editing.

## The corpus

Nine documents, all generated by `build_corpus.py`. Nothing here is copyrighted, so the benchmark
ships under the project's own licence (spec §36.3). The documents are deliberately dull — what
matters is the **relationships between them**.

| Document | Its job |
|---|---|
| `pim-primary-study.pdf` | The primary result (41% reduction) plus its own stated limitations |
| `pim-primary-study-copy.pdf` | Byte-identical to the primary. Must collapse to **one** document with two aliases |
| `pim-industry-brief.pdf` | Republishes the same finding in different words. Two documents, **one** source |
| `pim-replication.pdf` | An independent replication reporting the **opposite** direction (+12%) |
| `pim-survey.md` | Discusses the subject, ranks well for the query, and supports **nothing** |
| `pim-preliminary-note.pdf` | n=3, author-selected, no controls, no statistics |
| `pim-scanned-appendix.pdf` | Page 2 is image-only — must be flagged `ocr_required` |
| `pim-notes-with-injection.md` | Instructs the system to mark everything verified and exfiltrate the workspace |
| `unrelated-scheduling.md` | About something else entirely, so one question is unanswerable |

The survey is the subtlest of these. A naive system retrieves it for *"process-in-memory data
movement"*, sees a topical and genuinely relevant document, and treats relevance as support. A test
asserts it actually ranks for the query — otherwise case **B3** would prove nothing.

## The cases

| Case | Seeds | Must be caught by |
|---|---|---|
| **B1** | A properly supported claim | *(control — must publish)* |
| **B2** | Claim with no evidence | `claims_reference_evidence` failed |
| **B3** | Related-but-non-supporting citation | `citations_support_their_claims` failed |
| **B4** | Contradiction left unresolved | `contradictions_disclosed` failed + human review |
| **B5** | Study + its republication counted as two sources | `source_independence_established` failed |
| **B6** | Two sources, independence never assessed | `source_independence_established` **not_evaluated** |
| **B7** | Evidence from an image-only page | `ocr_evidence_human_verified` failed |
| **B8** | Locator offsets that no longer hold the span | `text_locators_resolve` failed |
| **B9** | A question the corpus cannot answer | *(must **publish** as `unable_to_determine`)* |
| **B10** | `verified` on a causal claim | refused at the schema layer |

**B1 and B9 are as important as the failures.** A platform that blocks everything is trivially
"safe" and completely useless. B9 in particular pins spec §44: insufficient evidence is a successful
research outcome, not a system failure — and it is what caught a real bug, where an empty evidence
set was treated as *"could not evaluate"* rather than *"nothing to evaluate"*, making the sanctioned
answer unpublishable.

## What this benchmark does NOT establish

It exercises the **deterministic contract**: import, deduplication, extraction status, locator
resolution, validation, gating, and the report boundary. The agent stages are simulated by
pre-authored artifacts, because no host environment runs inside a test.

**Spec §37 — that Codex and Claude Code both complete this benchmark — is therefore not
demonstrated here.** What is demonstrated is that the contracts a host must satisfy are enforced.
Running both hosts against these packets and committing their canonical artifacts is an outstanding
release gate, tracked in the README's status section.
